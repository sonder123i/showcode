# 一键查快递功能 - MuMu 模拟器测试指南

## 准备工作

### 1. 确认已安装的 APK
```bash
ls -la "/e/express/app/build/outputs/apk/debug/app-debug.apk"
```
文件大小应约为 **15.9 MB**

### 2. 启动 MuMu 模拟器
- 打开 MuMu 模拟器（端口 16416）
- 确保网络通畅

## 手动测试步骤

### 步骤 1: 安装新版 APK
```bash
# 方式 A: 拖拽安装
将以下文件拖入 MuMu 模拟器窗口：
/e/express/app/build/outputs/apk/debug/app-debug.apk

# 方式 B: 使用 adb（如果配置了 PATH）
adb -s 192.168.1.164:16416 install -r "/e/express/app/build/outputs/apk/debug/app-debug.apk"
```

### 步骤 2: 首页验证

#### 验证点 2.1: 有件时显示查快递按钮
1. 确保首页有至少一个取件点卡片
2. 检查顶栏右上角是否有**两个图标**：
   - 🔍 搜索框开关（放大镜）
   - 🔲 查快递按钮（方框放大镜）

#### 验证点 2.2: 无件时不显示查快递按钮
1. 清空所有待取件（或进入空态首页）
2. 检查顶栏是否**只显示搜索框图标**

### 步骤 3: 剪贴板自动填充测试

#### 测试用例 3.1: 标准快递短信格式
1. 在模拟器剪贴板粘贴以下内容：
   ```
   【丰巢】您有一个包裹已放入火星 1 号丰巢柜取件，取件码：7-1-3393，请及时取件。
   ```
2. 点击首页顶栏的**查快递按钮**（方框放大镜）
3. **预期结果**：
   - ✅ 输入框自动填入剪贴板内容
   - ✅ "自动提取"区域显示绿色文字：
     - 取件码：7-1-3393
     - 取件点：火星 1 号丰巢柜
   - ✅ 下方表单自动填充：
     - 取件码（已识别）：7-1-3393
     - 取件点（已识别）：火星 1 号丰巢柜
   - ✅ "保存并跳转"按钮可点击（蓝色高亮）

#### 测试用例 3.2: 菜鸟驿站格式
1. 清空输入框
2. 在剪贴板粘贴：
   ```
   您的包裹已到达向阳小区菜鸟驿站 (08 号店)，取件码：A12-5-2277，请凭码取件。营业时间 08:00-20:00。
   ```
3. 重新点击查快递按钮
4. **预期结果**：
   - ✅ 成功提取：
     - 取件码：A12-5-2277
     - 取件点：向阳小区菜鸟驿站

#### 测试用例 3.3: 无法识别的文本
1. 在剪贴板粘贴普通文本（非快递相关）：
   ```
   今天天气真好，适合出门逛街。
   ```
2. 点击查快递按钮
3. **预期结果**：
   - ✅ 红色提示："原文里没认出来，请手动填下面两项"
   - ✅ "保存并跳转"按钮禁用（灰色）

#### 测试用例 3.4: 剪贴板为空
1. 清空剪贴板
2. 点击查快递按钮
3. **预期结果**：
   - ✅ 输入框为空，等待用户手输
   - ✅ 红色错误提示出现

### 步骤 4: 手动补全流程测试

#### 测试用例 4.1: 部分识别失败
1. 在剪贴板粘贴：
   ```
   取件码 123456
   ```
   （缺少取件点信息）
2. 点击查快递按钮
3. **预期结果**：
   - ✅ 取件码被识别
   - ✅ 取件点字段为空
   - ✅ 用户需要手动填写"取件点名称"
   - ✅ "保存并跳转"按钮仍禁用（因为缺取件点）

4. 手动填写"取件点名称"为「测试驿站」
5. **预期结果**：
   - ✅ "保存并跳转"按钮变为可用（蓝色）
   - ✅ 点击后成功保存并返回首页

### 步骤 5: 历史记录测试

#### 测试用例 5.1: 历史列表展示
1. 完成多次成功的保存操作（5-10 次）
2. 再次打开查快递页面
3. **预期结果**：
   - ✅ 底部显示"最近查询 (N/10)"标题
   - ✅ 列出最多 5 条历史记录
   - ✅ 每条记录为可点击的 Card
   - ✅ 按时间倒序排列（最新的在最上面）

#### 测试用例 5.2: 历史记录回填
1. 点击任意一条历史记录
2. **预期结果**：
   - ✅ 该记录的完整文本填入输入框
   - ✅ 触发自动解析流程

#### 测试用例 5.3: 历史去重逻辑
1. 连续两次保存相同的快递短信
2. 再次打开查快递页
3. **预期结果**：
   - ✅ 同一条记录只出现一次（去重）
   - ✅ 新保存的记录排在最前面

### 步骤 6: 返回键与导航测试

#### 测试用例 6.1: 返回键行为
1. 在查快递页面（未保存）按返回键
2. **预期结果**：
   - ✅ 回到首页
   - ✅ 输入框清空
   - ✅ 提取结果清空

#### 测试用例 6.2: 保存成功后返回
1. 填写完整并点击"保存并跳转"
2. **预期结果**：
   - ✅ 返回首页
   - ✅ 新建的取件项出现在首页对应取件点卡片下
   - ✅ 再次打开查快递页，表单已清空

## 已知限制

### AC6 中的边界情况处理
- 若剪贴板包含图片/二进制数据 → `primaryText = null` → 视为空值处理
- 若文本中包含多条取件码 → 取第一个成功提取的
- 历史记录仅存内存态，App 重启后清空
